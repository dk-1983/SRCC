# Реализация и проверка

Статус: план. Сценарии ниже ещё не выполнены; наличие документа не означает аппаратную проверку или готовность интеграции к эксплуатации.

## Этапы реализации

| Этап | Результат | Условие завершения |
|---|---|---|
| 1. Контракты установки | Карта HA entities, readback, свежести и питания | Определены источники и достаточные доказательства каждого действия |
| 2. Чистое ядро | Модели, стратегия, guards, независимая аварийность | Unit-сценарии границ, плохих данных и UPS проходят без HA |
| 3. Наблюдение в HA | Config Flow, адаптеры чтения, sensors и diagnostics | Реальные данные объяснимы, исполнительные команды отсутствуют |
| 4. Исполнитель переходов | Очередь, readback, timeout, журнал и отмена | Проверки асинхронных переходов и отказов проходят на имитаторах |
| 5. Восстановление и управление | Manual switch, options, lifecycle и сервисы | Нет команд после manual/unload; восстановление не повторяет слепо intent |
| 6. Стенд | Проверка выбранных адаптеров и устройств | Подтверждены OFF, C.dr, задержки и поведение при потере связи |
| 7. Пилотная эксплуатация | Наблюдение, затем контролируемая автоматика | Утверждены настройки, аппаратный аварийный контур и критерии отката |

До этапа 6 требуется выбрать минимальную версию Home Assistant и тестовую матрицу. Готовые команды установки и значки CI добавляются после появления работающего пакета и проверок.

## Программные сценарии

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| T01 | Tout равна AC_HARD_MIN, ниже и чуть выше | На границе и ниже запуск запрещён; чуть выше нужны остальные guards |
| T02 | Колебания Tout вокруг normal limit | VENT → AC при Tout >= +1, AC → VENT при Tout <= −1; между порогами удерживать текущий пригодный режим, включая точку 0 |
| T03 | Условие перехода исчезло до condition_hold | Таймер сброшен, переключения нет |
| T04 | Истёк dwell, но условие нестабильно | Одного dwell недостаточно для смены режима |
| T05 | C.dr=0 подтверждён, выход ещё ON | COOL не отправляется |
| T06 | Выход OFF, но C.dr неизвестен или 1 | COOL не отправляется |
| T07 | OFF принят сервисом, AC ещё не подтверждён OFF | C.dr=1 не отправляется |
| T08 | AC unavailable после COOL | Состояние неопределённо, резервная вентиляция не включается без доказанного OFF |
| T09 | AC ожидает защиту компрессора | До согласованного deadline нет ложного отказа по тренду |
| T10 | Tin=27, Tout=30, AC недоступен | Вентиляция не запускается; при запросе охлаждения NO_COOLING_AVAILABLE |
| T11 | Tin−Tout достаточна, AC физически OFF | Резерв возможен при остальных условиях и наличии питания |
| T12 | On Battery без температурной необходимости | Автоматического включения вентилятора нет |
| T13 | UPS unavailable либо сигналы противоречат | Нет ложного MAINS; отдельная причина ограничения |
| T14 | Низкий заряд/runtime либо потеря одного источника | Исполняется выбранный профиль, отсутствующее значение не равно нулю |
| T15 | unknown/unavailable/NaN/неподходящие единицы каждого входа | Правильное качество и запрет зависимых действий |
| T16 | Температура постоянна, heartbeat продолжается | Значение не ошибочно помечается старым по last_changed |
| T17 | События прекращаются | Watchdog переводит сигнал в STALE без нового state event |
| T18 | Manual включён на каждой фазе перехода | После отключения автоматики новых команд нет, включая retry |
| T19 | Перезапуск после intent, но до/после service | Физическое состояние проверяется, команда слепо не повторяется |
| T20 | Старое сохранённое состояние расходится с readback | Приоритет фактического readback; UNKNOWN/CONFLICT видны оператору |
| T21 | Смена options/entities во время перехода | Старая generation не выдаёт дальнейших команд |
| T22 | Ответ или событие старой команды пришло поздно | Оно обновляет наблюдение, но не завершает чужую транзакцию |
| T23 | Пульт или сторонняя автоматизация вмешались | Расхождение замечено, нет бесконечной борьбы командами |
| T24 | Выход вентилятора ON, нет спроса ТРМ | Не объявляется специфический отказ вентиляции по неполному условию |
| T25 | Рост Tin после grace при устойчивом запросе | Подозрение неэффективности с доказательствами, а не диагноз поломки |
| T26 | Тренд прерывается, режим сменяется | Окно сбрасывается, нет переноса старого отказа на новый режим |
| T27 | CRITICAL и Tin стала недоступна | Авария не снимается по отсутствию данных |
| T28 | Сброс диагностической ошибки при реальном fault | Активный fault и hard guards остаются |
| T29 | Запись Store повреждена или версия несовместима | Команд по повреждённым данным нет; диагностика и reconciliation |
| T30 | Изменение системного времени | Живые таймеры монотонны; после рестарта выдержки не сокращаются небезопасно |
| T31 | Два ConfigEntry используют один привод | Второй владелец не создаётся |
| T32 | Ошибка сервиса, timeout или отмена задачи | Нет ложного успеха и неограниченного retry |
| T33 | Tin потеряна / Tout пересекла hard-min при работающем AC | Проверяется выбранная и документированная эксплуатационная политика |
| T34 | Вентиляция неэффективна и AC заблокирован | Нет бесконечного выбора того же неэффективного резерва |

| T35 | Штатный режим, Tout < 0 °C, запрос холода ТРМ отсутствует | C.dr=1 сохраняется при подтверждённом AC OFF; SRCC не блокирует ТРМ по дополнительному порогу Tin |
| T36 | Подтверждённая вентиляция, Tout >= +1 °C | Целевое C.dr=0; COOL не отправляется до подтверждения запрета и снятия выхода |

| T37 | Вентиляция отказала, Tout=−2 °C, охлаждение необходимо | AC допускается как резерв только после всех подтверждений и guards |
| T38 | Вентиляция отказала, Tout=−5 °C или −9 °C | Запуск AC запрещён даже при CRITICAL; NO_COOLING_AVAILABLE при отсутствии допустимого охлаждения |

| T39 | Tout внутри согласованной полосы гистерезиса, предыдущие режимы разные | Каждый пригодный подтверждённый режим удерживается до своего порога; колебания не вызывают переключений |
| T40 | Холодный старт внутри полосы / потеря пригодности удерживаемого режима | Применяется начальное правило или новый допустимый маршрут; удержание неизвестного/непригодного режима запрещено |
| T41 | Tout < 0 °C, вентиляция исправна, запрос штатного запуска AC | Новый штатный запуск AC не допускается; аварийный резерв проверяется отдельно |

| T42 | Вентиляция отказала, Tout=−7 °C, охлаждение необходимо | Hard-min −5 °C блокирует резервный AC; аварийность не снимает запрет |

| T43 | Tout около −40 °C, C.dr=1, ТРМ редко требует охлаждение | Редкие включения вентилятора не считаются отказом; AC заблокирован по hard-min, HEAT не запрашивается |
| T44 | Climate поддерживает HEAT/AUTO/HEAT_COOL, Tin снижается | SRCC не отправляет режимы обогрева или автоматического выбора; допустимы только OFF/COOL и уставка охлаждения |
| T45 | Внешнее управление установило HEAT/AUTO/HEAT_COOL | Этот режим не принимается за OFF; вентиляция не разрешается без подтверждения выключения AC |

| T46 | AC работает, Tout=−0.5 °C; затем Tout=−1 °C | В первом случае режим удерживается, во втором рассматривается переход к вентиляции с выдержками и readback |
| T47 | Вентиляция работает, Tout=+0.5 °C; затем Tout=+1 °C | В первом случае режим удерживается, во втором рассматривается переход к AC с выдержками и readback |
| T48 | Стойка перегревается при вентиляции до верхнего порога Tout | Проверяется будущая согласованная политика резервного перехода по температуре стойки; hard-min и interlock не обходятся |

В тестах использовать управляемые часы и последовательности событий. Проверять не только итоговый режим, но также порядок команд, отсутствие запрещённых вызовов, reason_code и качество доказательств. Таймеры не проверять реальными многоминутными ожиданиями.

Для HA: Config Flow и миграции, setup/unload, подписки, platform state, ошибки service, service schema и восстановление ConfigEntry. Перед релизом — применимые проверки HA manifest/переводов, статический анализ и тесты на заявленных версиях.

## Аппаратные проверки

1. Проверить значения C.dr=0/1 и независимость readback от отправленной команды. Зафиксировать задержку снятия выхода.
2. При C.dr=1 проверить, что ТРМ самостоятельно включает и выключает выход. SRCC не регулирует вентилятор по собственному короткому циклу.
3. Проверить OFF/COOL и уставку Haier: какие состояния optimistic, какие подтверждают устройство, когда появляется фактическое OFF.
4. Проверить нормальную защитную задержку компрессора без её обхода. Отдельно измерить время подтверждения команды и начала охлаждения.
5. Проверить потерю связи с работающим AC: логическая unavailable не должна разблокировать вентиляцию.
6. По утверждённой схеме стенда проверить потерю сети, питание каждого устройства, сигнал on_battery и восстановление сети. Изменение питания серверной без отдельной процедуры испытаний не требуется.
7. Проверить автоматическое восстановление режима Haier после возврата сети при разрешённой резервной вентиляции. Подтвердить способ исключения одновременного включения до реакции HA; при необходимости использовать аппаратный interlock.
8. Проверить возраст данных при неизменной температуре и физическом отключении источника.
9. Выполнить перезапуск HA в каждой фазе перехода, включая промежуток между отправкой и readback.
10. Проверить выключение автоматики, ручное изменение оборудования и последующее reconciliation.
11. Проверить резерв только при полезном delta, а горячий наружный воздух смоделировать на тестовых входах.
12. Убедиться, что независимая аппаратная сигнализация/защита действует при неработающем HA. SRCC не выдаёт команды EPO.

Протокол испытаний содержит версии HA и интеграций оборудования, назначенные роли, настройки, временную шкалу команд/readback, ожидаемый и фактический результат. Публикуемые примеры обезличиваются. Невыполненный сценарий отмечается как невыполненный, а не «условно пройденный».

## Готовность к пилоту

Автоматика допускается после согласования обязательных политик, подтверждения readback и схемы питания, прохождения сценариев взаимного исключения/восстановления и наличия независимой аппаратной защиты. При недостаточных сигналах допустим режим наблюдения с явно обозначенными ограничениями.
